# 操作系统

操作系统把物理内存分成每个进程自己的虚拟地址，再把磁盘变成文件。这一页用一次页表行走和一次 `write` 的七步把这两件事算完。

## 虚拟地址 0x00401234 怎样变成物理地址

源码 [PageTableWalk.java](../demos/src/PageTableWalk.java)，输出 [PageTableWalk.txt](../demos/transcripts/PageTableWalk.txt)。

演示用 4096 字节的页。虚拟地址除以 4096 得到页号，余数是页内偏移。页表记录页号到物理页号的映射，以及这一页在不在内存里。

第一次，地址 `0x00401234`：

1. `0x00401234 / 4096 = 0x401`，所以 vpn 是 `0x00401`。
2. `0x00401234 % 4096 = 0x234`，偏移是 `0x234`。
3. 页表里这一项存在，物理页号 pfn 是 `0x12AB`。
4. 物理地址把 pfn 左移 12 位再或上偏移：`0x12AB000 | 0x234 = 0x12AB234`。

CPU 里的内存管理单元做的就是这四步。演示把页表放在数组里，是为了把除法和查表打印出来。真实的多级页表用虚拟地址的几段分别索引每一级，目的相同：不要用一整张覆盖全部地址空间的扁平表。

第二次，地址 `0x00402000`：

1. vpn 是 `0x00402`，偏移是 0。
2. 页表项不存在。内存管理单元无法完成翻译，CPU 进入缺页异常，把控制权交给内核。
3. 内核可以选择分配一个物理页、从文件读入，或判定这次访问非法并给进程发信号。
4. 演示走第一条：装入 pfn `0x55`，再翻译 `0x00402010`，得到物理地址 `0x55010`。

```text
虚拟地址 0x00401234
  页号 vpn=0x00401  页内偏移=0x234
  物理页 pfn=0x12AB  物理地址=0x12AB234
虚拟地址 0x00402000
  页号 vpn=0x00402  页内偏移=0x000
  页表项不存在，CPU 触发缺页，交给内核
缺页处理后装入物理页 0x55
虚拟地址 0x00402010
  页号 vpn=0x00402  页内偏移=0x010
  物理页 pfn=0x55  物理地址=0x55010
```

Java 堆是一块虚拟地址连续的区间。物理页可以不连续，也可以在第一次写入时才真正分配。`MappedByteBuffer` 把文件映射进这段地址，访问内存就等于访问文件页。崩溃报告里的地址是虚拟地址。

## `fork` 为什么可以很快

创建进程时，子进程需要一份地址空间。复制每一页的代价很大，所以内核先让两份页表指向同一批物理页，并标成只读。任何一边写入时才缺页，内核再复制那一页。这就是写时复制。随后 `exec` 换上新程序，没写过的页就不必复制。

## write 返回和掉电

源码 [WritePath.java](../demos/src/WritePath.java)，输出 [WritePath.txt](../demos/transcripts/WritePath.txt)。七步的数据位置：

1. 用户缓冲区：4096 字节在进程的 `byte[]` 里。
2. 系统调用：CPU 从用户态陷入内核，内核检查文件描述符属于这个进程，并且用户地址可读。
3. 页缓存：内核找到文件中对应的那一页。页不在内存就先读进来或分配，然后把 4096 字节拷进去，页变脏。
4. `write` 返回：系统调用结束，进程继续。磁盘介质上可能还是旧字节。
5. 进程崩溃：内核还在，脏页还在。
6. 整机掉电：没有 `fsync` 时脏页消失，磁盘仍是旧内容。
7. `fsync`：内核把脏页和文件系统自己的日志写到设备，等到设备确认才返回。

```text
1. 用户缓冲区：Java 把 4096 字节放进堆里的 byte[]。
2. 系统调用 write：CPU 陷入内核，检查文件描述符和地址。
3. 页缓存：内核把这 4096 字节拷进对应文件页，页被标成脏。
4. write 返回：调用方以为写完了。磁盘上的旧页还在。
5. 进程崩溃：页缓存还在，数据还在。
6. 整机掉电：没有 fsync 时，脏页丢失，磁盘仍是旧内容。
7. fsync：内核把脏页和文件系统日志写到盘，并等待设备确认。
```

文件描述符是进程里的一个整数，内核用它找到打开文件表。表项里有当前偏移。两个描述符指向同一表项时，偏移会一起变。

线程切换时内核保存寄存器，若换的是另一个进程还要换页表。Java 线程池用少量内核线程消化大量任务，就是为了少做这种切换。虚拟线程把“阻塞时让出”放进 JVM 之后，内核调度的仍是那一小批载体线程。

等待锁需要睡觉时，Linux 用 futex：用户态先用原子变量看一眼，确实要等才进入内核。Java 重量级监视器的阻塞会走到这类等待。
