# 操作系统

操作系统把一套物理 CPU 和一块物理内存，分成许多进程各自以为独占的机器，再把磁盘和网卡变成文件和套接字。Java 线程、堆和文件描述符都是对这层抽象的再包装。

## 进程、线程、地址空间

进程是资源的边界：一份地址空间、一组打开的文件、一个用户身份。线程是进程里的一条执行流，共享这份地址空间，各自有栈和寄存器现场。

所以 Java 里同一个堆上的对象，可以被多个线程看到。可见性要靠语言内存模型来约束，内核只保证它调度线程时保存和恢复寄存器。

创建进程时，Unix 的经典做法是复制父进程的地址空间。复制是惰性的：页表先标记为写时复制，真有写入才分配新物理页。这就是 `fork` 便宜、随后 `exec` 换上新程序的原因。

## 虚拟内存

每个进程看到的地址是虚拟地址。内存管理单元按页表把它译成物理地址。页不在内存里时产生缺页，内核可以选择从文件读入、分配零页，或判定为非法访问并给进程发信号。

这解释了几件 Java 里看得到的事：

- 堆是一块被虚拟内存撑起来的连续地址。物理页可以不连续，也可以还没真正分配。
- 栈溢出是访问到了栈保护区。
- `MappedByteBuffer` 把文件映射进地址空间，访问内存就等于访问文件页。
- 进程崩溃报告里的地址是虚拟地址。

页缓存把最近用过的文件页留在内存里。应用写文件，常常是先写到页缓存，再由内核回写磁盘。所以「write 返回了」不等于「掉电后还在」。数据库用自己的刷盘和预写日志来补上这个差距。

## 调度

内核在线程阻塞、时间片用完或有更高优先级线程就绪时切换。切换要保存寄存器、换地址空间（若跨进程）并跳到另一条线程。这个成本就是上下文切换。

Java 线程池的目的，是用少量内核线程消化大量任务，避免为每个请求都做一次线程创建和切换。虚拟线程把「阻塞时让出载体线程」放进了 JVM，内核调度的仍是那一小批载体线程。

## 文件和 VFS

虚拟文件系统给上层统一的 `open`、`read`、`write`、`close`。具体文件系统（ext4、XFS 等）实现目录项、inode 和块分配。inode 描述文件的元数据和块位置，目录是名字到 inode 的映射。

打开文件在进程里变成一个文件描述符，内核里是一份打开文件表项，里面有当前偏移。多个描述符可以指向同一份打开文件，所以偏移会一起变。

## 同步落到内核

用户态自旋在短临界区有意义。等锁要睡觉时，Linux 用 `futex`：用户态先用原子变量判断，真正需要阻塞才进内核。Java 的 `LockSupport.park` 和重量级监视器，最终会走到这类内核等待。

## 系统调用边界

用户态不能直接关中断或读写设备寄存器。它通过系统调用陷入内核，内核检查参数后再做。一次 `read` 的成本里，有参数检查、可能的阻塞、把数据拷到用户缓冲区。减少系统调用次数，是 NIO、缓冲流和批量写存在的原因。
