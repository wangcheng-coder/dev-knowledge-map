# Java 数据访问

业务对象落进数据库、缓存和消息系统时，正确性来自持久化协议，性能来自缓冲、批量和分区。文件系统页缓存和「write 返回不等于已落盘」在 [操作系统](../os/README.md)。

## JDBC

JDBC 是数据库连接的标准 API。驱动把 SQL 和参数发给数据库，再把结果行拉回。连接建立很贵，所以用连接池复用物理连接。池要有上限，业务在持有连接期间做的事要短，远程调用不要夹在持连接的区间里。

参数用占位符绑定。拼接 SQL 既难读，也会把输入变成语句结构。

批量把多行放进一次网络往返。事务把多条语句收成一个提交单位。自动提交打开时，每条语句自己就是一个事务。

## 事务隔离

数据库用锁和多版本来决定一个事务能看见什么。隔离级别从低到高，限制越强，并发越差。开发时要能对上这几个现象：

| 现象 | 含义 |
| --- | --- |
| 脏读 | 读到了别的事务还没提交的写入 |
| 不可重复读 | 同一事务里两次读同一行，行被别的事务改了 |
| 幻读 | 同一范围查询两次，出现了新的行 |

多数业务库默认已提交读：语句只能看见已提交数据，长事务仍然会挡住清理或扩大锁范围。事务里只放必须原子完成的写入和它依赖的读取。

Spring 对事务的传播和回滚规则在 [框架](frameworks.md)。这里的规则是数据本身的规则：提交成功之后，其他连接按隔离级别才能看见。

## 映射

MyBatis 把 SQL 留在映射文件或注解里，按行组装对象。SQL 可见，便于对照执行计划。N+1 次查询来自循环里逐条加载关联，改成连接或按主键批量查。

Hibernate 把对象图和表对应起来，用脏检查决定更新哪些列，用一级缓存保证同一持久化上下文里标识相同的实体只有一份。懒加载要在会话还开着的时候触发。跨服务把持久化实体直接当接口对象传来传去，会把会话和懒加载泄漏到边界外。

## 缓存

缓存保存可以重建或可以过期的结果。先定失效：谁在写入数据库后删掉缓存，过期时间是多少，缓存挂了是否可以直接打到数据库。

Redis 的值类型决定用法：字符串适合简单对象，哈希适合字段更新，列表和流适合队列式数据，有序集合适合排名。键要有过期和容量预算。Lettuce 基于 Netty，客户端线程模型要和连接数一起看。

本地缓存适合单机内重复读取。Caffeine 提供基于容量和时间的本地缓存，并处理并发加载。多实例部署时，本地缓存的失效要有额外广播，否则各实例看到的过期点不同。

## 消息

Kafka 把日志按主题分成分区。分区内有序，消费组里的一个分区同时只给一个消费者。位移提交表示处理进度。先处理后提交，崩溃会重复；先提交后处理，崩溃会丢失。业务侧用幂等把重复变成安全的。

消费线程数和分区数要一起设计。把处理失败的消息无限制地立即重试，会堵住分区后面的消息。
