# Java 数据访问

数据页的两个演示是隔离级别和 `write` 返回的含义：[IsolationSim.txt](../demos/transcripts/IsolationSim.txt)、[WritePath.txt](../demos/transcripts/WritePath.txt)。JDBC、映射、缓存和 Kafka 按同一种读法写：每一步谁持有数据，下一步失败时数据留在哪。

## 三种读法各自看见什么

源码 [IsolationSim.java](../demos/src/IsolationSim.java)。账户初始已提交余额是 10。

场景 1，读未提交：

1. T2 写入 40，只放在 `pending`，`committed` 仍是 10。
2. 读未提交直接看 `pending`，得到 40。
3. T2 回滚，`pending` 丢掉。40 从未成为提交结果。已经拿着 40 去做决定的事务，用了一个不存在的值。

场景 2，读已提交：

1. T1 第一次只看 `committed`，得到 10。
2. T2 把 40 提交，`committed` 变成 40。
3. T1 第二次再看 `committed`，得到 40。同一个事务里两次普通读取结果不同，这就是不可重复读。

场景 3，可重复读：

1. T1 开始时记下快照 10。
2. 之后即使提交值变成 70，T1 仍按快照读 10。新开的事务才看见 70。

```text
场景 1  读未提交
  已提交余额 10
  T2 把余额改成 40，还没提交。读未提交读到 40
  T2 回滚。那个 40 从未成为事实，已提交余额回到 10
场景 2  读已提交，两次普通读取
  T1 第一次读取 10
  T2 提交 40 之后，T1 第二次读取 40。同一事务里两次结果不同，这是不可重复读
场景 3  可重复读使用第一次的快照
  T1 快照仍是 10，提交后的新值是 70
```

幻读是范围上的同类问题：同一条范围查询第二次执行时，别的事务插入了满足条件的新行。演示里的单行模型不产生新行，所以没有单独打印幻读。

数据库用锁或多版本实现这些规则。事务里只放必须原子完成的读写。连接在整个事务期间被这条业务占着，远程调用不要夹在持连接的区间里。

## `write` 返回时数据在哪

源码 [WritePath.java](../demos/src/WritePath.java)，输出 [WritePath.txt](../demos/transcripts/WritePath.txt)。

1. Java 把 4096 字节放在堆里的 `byte[]`。
2. `write` 系统调用陷入内核，检查文件描述符和用户地址。
3. 内核把这 4096 字节拷进页缓存里的文件页，页被标成脏。
4. `write` 返回。调用方继续往下走。磁盘上的那一页可能还是旧的。
5. 进程崩溃时，页缓存还在，数据还在。
6. 整机掉电，没有 `fsync` 的脏页会丢，磁盘仍是旧内容。
7. `fsync` 把脏页和文件系统日志写到设备，并等待设备确认，然后才返回。

数据库不信任第 4 步。它先把修改写进预写日志并要求日志落盘，再认为事务提交了。崩溃恢复时用日志把页重做回来。

## JDBC 一次插入的步骤

1. 从连接池取一条已经建立的物理连接。建连的成本在借出之前已经付过。池有上限，借出的连接必须归还。
2. 连接上若开着自动提交，这一条语句自己就是一个事务。要和后面的语句放在一起，就先关掉自动提交，或进入框架的事务。
3. SQL 文本里用占位符。驱动按类型发送参数，数据库按语句结构解析。参数值不会变成新的 SQL 片段。
4. 数据库在缓冲池里找到数据页，写预写日志，再改页。
5. 提交成功后，其他“读已提交”的事务才能看见新行。
6. 把连接还回池。还回之前要结束事务，否则下一个借用者继承未提交的状态。

多行插入能放进同一次网络往返时用批量接口。循环里逐条查询关联行，会把一轮业务变成 N 加 1 次往返。

MyBatis 把 SQL 留在映射里，按行组装对象。会话、执行器和映射从这里看：https://github.com/mybatis/mybatis-3

Hibernate 在同一个持久化上下文里用标识保证同一行只有一个对象，用脏检查决定更新哪些列。懒加载要在会话还开着时触发。不要把还连着会话的实体直接传到别的进程。https://github.com/hibernate/hibernate-orm

## 缓存和消息

缓存保存能重建或能过期的结果。写入数据库成功之后删除对应缓存，并给缓存一个过期时间。缓存失效时，请求要能直接落到数据库，同时数据库要受得住这批请求。

Redis 的字符串、哈希、列表、流和有序集合是不同的值结构。键要有过期和容量。Lettuce 用 Netty 发命令：https://github.com/redis/lettuce ，服务端结构在 https://github.com/redis/redis 。

Kafka 的分区内有序。一个消费组里，一个分区同时只交给一个消费者。先处理再提交位移，崩溃会重复；先提交再处理，崩溃会丢。业务用幂等把重复变成安全的。失败消息若立刻无限重试，会堵住这个分区后面的消息。https://github.com/apache/kafka

结构变更按版本执行，用 Flyway 这类迁移留在仓库里：https://github.com/flyway/flyway 。数据库自己的事务和预写日志以 PostgreSQL 为对照：https://github.com/postgres/postgres 。
