# Java 并发

并发要同时看三件事：线程在哪个核上跑，写入什么时候能被另一个线程看见，共享结构在竞争下如何保持不变量。CPU 缓存和指令重排的硬件背景在 [硬件](../hardware/README.md)，内核如何阻塞线程在 [操作系统](../os/README.md)。

## 可见性：happens-before

Java 内存模型用 happens-before 规定哪些写入一定能被后面的读取看到。下面这些关系成立时，前面的写入对后面的读取可见：

- 同一个线程里，程序顺序靠前的动作先于靠后的动作。
- 对一个监视器的解锁，先于随后对同一监视器的加锁。
- 对 `volatile` 字段的写入，先于随后对它的读取。
- 线程启动之前的写入，对新线程可见；线程结束后的写入，对成功 `join` 的线程可见。
- happens-before 可以传递。

没有这层关系时，另一个线程可以一直看到旧值，也可以看到字段只更新了一半。不可变对象发布出去之后不再修改，读取方就不需要额外同步。

`volatile` 保证可见性和禁止把该变量的读写排到屏障的错误一侧，不保证 `count++` 这种读改写是原子的。读改写要用原子类或锁。

## 锁

`synchronized` 锁定的是对象监视器。进入和退出与监视器的加锁解锁对应，并且临界区内抛异常也会释放。JDK 15 起偏向锁默认关闭，后来的版本移除了偏向锁，当前实现围绕轻量级锁和重量级监视器。重量级路径会把等待线程放进内核。

`java.util.concurrent.locks` 里的锁多数建在 AQS 上。AQS 用一个原子状态表示资源，没抢到的线程进入等待队列。读源码时先看状态取值的含义，再看入队和唤醒。`ReentrantLock` 是独占且可重入，`Semaphore` 是计数，`CountDownLatch` 是一次性的到达计数。

## 线程池

线程池把任务和内核线程拆开。`ThreadPoolExecutor` 里要同时看懂：核心线程数、最大线程数、队列、拒绝策略、空闲回收。任务先占满核心线程，再进队列，队列也满了才把线程数扩到最大。队列如果无界，最大线程数就没有机会生效，任务会堆在内存里。

每个任务要有界：会结束，或能响应中断。线程池关闭时先停止接收，再按选择等待已提交任务或尝试中断。

`ForkJoinPool` 适合可以把工作拆成子任务、子任务结束再合并的计算。工作窃取让空闲线程从别的队列尾部拿任务。它不适合里面再做会长时间阻塞的 I/O，除非使用专门为阻塞准备的管理方式。

## 虚拟线程

JDK 21 的虚拟线程由 JVM 调度到少量载体平台线程上。阻塞式的套接字和大量 JDK I/O 会在阻塞时让出载体，因此可以用「一请求一线程」的写法承载大量并发连接。

在 `synchronized` 或本地方法里阻塞时，虚拟线程可能钉在载体上，载体就没法去运行别的虚拟线程。热路径上的阻塞点要看它会不会钉住载体。版本之间这段行为在继续变化，以所用 JDK 的发行说明为准。

虚拟线程便宜的是阻塞和数量，不是把 CPU 计算变成并行。CPU 密集的任务数量仍然受核数限制。

## 并发容器

`ConcurrentHashMap` 允许并发读写，桶在冲突升级时用同步保护，计数值用分片累加减少争用。它的迭代器是弱一致的，不抛 `ConcurrentModificationException`，也不保证遍历到迭代开始之后的全部插入。

`BlockingQueue` 把生产和消费的等待放进队列实现。用它连接线程时，要定容量，让生产速度超过消费时在队列上阻塞，而不是把堆撑满。

`ThreadLocal` 把数据绑到线程。池化线程会复用，用完必须移除，否则下个任务读到上个任务的值，线程池也会把类加载器间接留住。

## 异步组合

`CompletableFuture` 把「完成之后接着做」显式写成阶段。每个阶段使用哪个执行器要写明。默认公共池被阻塞任务占满时，不相关的异步阶段会一起变慢。超时、异常和取消要在链上处理，避免未来永远不完成，调用方一直等。
