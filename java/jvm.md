# JVM

JVM 把 `class` 文件执行起来，并管理堆、代码优化和线程调度的用户态部分。HotSpot 是 OpenJDK 里的主要实现。读源码时把 `src/java.base` 当成 Java 写的核心库，把 `src/hotspot` 当成虚拟机本身。

## 类文件与加载

`javac` 产出的类文件包含常量池、字段、方法字节码和属性。虚拟机在定义类之前做格式和字节码验证。

类加载器把字节流定义成运行时的 `Class`。一个类的身份是「由哪个加载器定义」加上全限定名。同一个类文件被两个加载器各定义一次，得到的是两个类。

委派模型让加载请求先交给父加载器。核心类因此由启动类加载器统一定义，应用里不容易冒出第二份 `java.lang.Object`。需要打破委派的场景要有明确原因：应用服务器让 Web 应用先加载自己的类，SPI 用线程上下文类加载器去找服务实现。

类初始化发生在首次主动使用时。初始化会执行静态字段赋值和静态块，并先初始化父类。

## 运行时数据区

| 区域 | 内容 | 出错时常见表现 |
| --- | --- | --- |
| 程序计数器 | 当前线程执行到的字节码位置 | 线程私有，不会单独撑爆 |
| 虚拟机栈 | 栈帧：局部变量、操作数栈、返回点 | 栈深度过大时 `StackOverflowError` |
| 本地方法栈 | 本地调用的栈 | 本地崩溃 |
| 堆 | 实例和数组 | 回收跟不上分配时 `OutOfMemoryError` |
| 元空间 | 类的元数据 | 动态生成过多类时元空间耗尽 |

对象头里有标记字和类型指针，后面是字段，末尾按对齐补齐。压缩普通对象指针在堆不太大时用 32 位表示引用。JOL 可以打印真实布局，用来核对填充和对象大小，而不是凭字段个数估算。

## 垃圾回收

回收器从根集合出发找出还能到达的对象。根包括线程栈里的引用、静态字段和 JNI 引用。到达不了的对象可以被回收。

分代假设认为大多数对象很快就死。分代收集把精力放在年轻对象上，让短期对象廉价地消失。长期活着的对象晋升到老年代，避免被反复扫描。

| 收集器 | 它主要解决的问题 | 阅读时抓住的结构 |
| --- | --- | --- |
| Serial / Parallel | 实现简单，或用多线程提高吞吐量 | 年轻代拷贝，老年代整理 |
| G1 | 在大堆上把停顿拆到区域里控制 | 把堆分成等大区域，混合回收时挑选垃圾比例高的区域 |
| ZGC | 把停顿压到与堆大小关系很弱 | 并发标记和重定位，用读屏障保证搬迁时仍能访问 |

选择收集器是在吞吐、停顿和额外内存之间取舍。JDK 21 及之后把分代 ZGC 作为低延迟方向的主线，具体默认值以所用发行版的发布说明为准。

GC 日志和堆转储是证据。先看分配速率和晋升，再决定是收紧对象生命周期，还是调整堆。先用日志确认是哪一代在回收，再改业务里的对象寿命。

## 执行引擎

字节码先由解释器执行，热点方法交给即时编译器。分层编译里，C1 很快产出带性能计数的代码，C2 做更重的优化。优化建立在运行期观测上：分支走向、调用目标、类型是否稳定。

假设失效时虚拟机会去优化，退回解释或重新编译。所以微基准如果没跑过预热，测到的是解释和编译混在一起的时间。JMH 用来处理预热、死代码消除和多次迭代。

逃逸分析如果证明对象不会逃出方法，可以把它拆成标量，分配随之消失。这是「新对象不一定碰到堆」的原因，也是不能用微基准里的分配次数代替生产路径的原因。
