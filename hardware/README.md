# 硬件

软件的时间、并发和 I/O 模型，都建立在这一层已经做出的取舍上。CPU 一次只能按指令推进；存储离 CPU 越远越慢；设备用中断和 DMA 把「数据到了」这件事通知系统。

## 指令怎样被执行

一条指令从内存进入 CPU，大致经过取指、译码、执行、访存、写回。程序计数器指出下一条指令的地址。寄存器保存当前运算的操作数。算术逻辑单元完成加减和逻辑运算。控制单元按操作码决定打开哪条数据通路。

流水线把这几步重叠起来，所以一条分支猜错时要冲掉已经取进来的指令。乱序执行让后面不依赖结果的指令先做，再按程序顺序提交。对 Java 开发者，这意味着：源代码里的先后，在 CPU 上可以重排；`volatile` 和锁要表达的，就是哪些重排不能越过。

## 存储层次

CPU 不直接在磁盘上运算。数据要先进入主存，热数据再进入缓存，正在用的值放进寄存器。

| 位置 | 谁在用 | 开发时要记住的事 |
| --- | --- | --- |
| 寄存器 | 当前指令 | 数量很少，编译器和 JIT 负责分配 |
| L1 / L2 / L3 缓存 | 核内或核间 | 按缓存行搬运。相邻数据一起被带进来，这就是空间局部性 |
| 主存 | 进程看到的内存 | 延迟比缓存高一个数量级以上 |
| SSD / HDD | 文件系统和数据库 | 一次随机读的成本远高于内存访问 |

缓存行是搬运单位。两个核频繁写同一缓存行里的不同变量，会不断作废对方的副本，这叫伪共享。Java 里紧挨着的两个被高频更新的字段，可能就落在同一行。

多核各自有缓存时，要有协议保证大家看到的内存一致。MESI 是常见的教学模型：一行可以处于已修改、独占、共享或无效。锁和 `volatile` 最终都要落到这类缓存一致性动作和内存屏障上。

## 设备、中断、DMA

设备寄存器映射在一段地址上。CPU 可以轮询状态位，也可以等设备拉中断。中断会打断当前指令流，进内核的中断处理，处理完再回去。中断里只适合做很短的事，把耗时工作交给下半部或线程。

大批量数据用 DMA：设备直接读写内存，CPU 只在传输开始和结束时介入。网卡收包、磁盘读写都是这条路。所以上层看到的「读一次 socket」并不是 CPU 把网线电平逐位搬进 Java 堆。

## 和下一层的接口

固件和操作系统看到的硬件合同是：

- 复位后从哪条地址取第一条指令
- 中断向量表放在哪
- 物理地址如何通过页表变成虚拟地址（内存管理单元负责翻译）
- 哪些指令是特权指令，用户态不能直接执行
