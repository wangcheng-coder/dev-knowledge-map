# 硬件

硬件这一层用一条真实编码的加法指令、一张缓存行地址图，以及一轮 MESI 状态变化说明三件事：指令怎样流过 CPU，相邻字段为什么会互相拖慢，多核缓存怎样保持同一行数据只有一个事实。

## 一条 `add x1, x2, x3` 怎样被执行

RISC-V 的 R 型加法 `add rd, rs1, rs2` 使用操作码 `0110011`，`funct3=000`，`funct7=0000000`。取 `rd=x1`，`rs1=x2`，`rs2=x3`，拼出来的指令字是 `0x003100B3`。

按字段切开：

| 字段 | 位 | 值 | 含义 |
| --- | --- | --- | --- |
| funct7 | 31–25 | 0000000 | 这是加法，不是减法 |
| rs2 | 24–20 | 00011 | 第二个源寄存器 x3 |
| rs1 | 19–15 | 00010 | 第一个源寄存器 x2 |
| funct3 | 14–12 | 000 | 运算种类里的 add |
| rd | 11–7 | 00001 | 结果写入 x1 |
| opcode | 6–0 | 0110011 | 寄存器之间的整数运算 |

假设执行前 `x2=20`，`x3=22`，`pc` 指向这条指令。流水线里的这一条指令依次做：

1. 取指。用 `pc` 访问指令缓存。命中则得到 `0x003100B3`，`pc` 变成下一条的地址。未命中就等待从内存装入一整行指令。
2. 译码。按上面的表拆字段，控制单元打开“读两个寄存器、做加法、写回 rd”的数据通路。
3. 读寄存器。从寄存器堆读出 x2 和 x3，得到 20 和 22。
4. 执行。算术逻辑单元计算 `20+22=42`。这一步不访问数据内存。
5. 写回。在后面的节拍把 42 写入 x1。若后面的指令马上读 x1，转发电路可以直接把 42 送过去，不必等它先落回寄存器再读出来。

分支预测失败时，已经取进流水线的后续指令要被清掉。乱序执行可以让后面不依赖 x1 的指令先做，但写回对程序员可见的寄存器状态时仍按程序顺序。Java 里 `volatile` 和锁要表达的，就是哪些读写不能被这种重排拆开。细节在 [并发](../java/concurrency.md)。

Nand2Tetris 把从与非门到这条数据通路的过程做成了可做的课程：https://github.com/nand2tetris/nand2tetris 。指令位的合同在 https://github.com/riscv/riscv-isa-manual 。可综合的 CPU 在 https://github.com/openhwgroup/cva6 的 `core/`。QEMU 用软件实现同一份合同：https://github.com/qemu/qemu 。

## 缓存行：相邻 8 字节属于同一行

源码 [FalseSharing.java](../demos/src/FalseSharing.java)，输出 [FalseSharing.txt](../demos/transcripts/FalseSharing.txt)。

CPU 不按一个字段去内存取数，而按缓存行。演示把行长定为 64 字节，行首对齐在 `0x1000`。

```text
缓存行大小 64 字节。教学地址从 0x1000 对齐到行首。
a 在 0x1010，属于行 0x1000
紧挨着的 b 在 0x1018，属于行 0x1000
同一行: true
Core0 写 b 时，整行标成已修改，Core1 上 a 的副本一起作废。
把 b 放到 0x1050 后，属于行 0x1040
这时写 b 不再作废 a 所在的那一行。
```

`0x1010` 和 `0x1018` 相差 8。行号用地址去掉低 6 位得到，两个地址的行号都是 `0x1000`。Core0 只改 b，一致性协议仍把整行标记为已修改，Core1 上 a 的副本也失效。Core1 再读 a 时要重新取得这一行。两个核频繁写同一行里的不同字段，就会一直在传递这一整行。把 b 挪到 `0x1050`，行号变成 `0x1040`，写 b 不再碰 a 的那一行。

这是地址模型，不是某次计时。对象头会把真实字段的起始地址垫偏，两个 `long` 是不是同行要用布局工具看。模型说明的是：行是搬运和作废的单位。

## MESI：一行在两个核上的五种变化

源码 [MesiSim.java](../demos/src/MesiSim.java)，输出 [MesiSim.txt](../demos/transcripts/MesiSim.txt)。

四个状态的含义：

| 状态 | 这一核上的副本 |
| --- | --- |
| INVALID | 没有可用副本 |
| EXCLUSIVE | 只有我有，内容和内存一致 |
| SHARED | 还有别的核有，内容和内存一致 |
| MODIFIED | 只有我有，内容和内存不同，我必须负责写回 |

演示按一次读、再一次读、一次写、再一次读推进：

```text
初始，两个核都没有这行缓存
  Core0=INVALID  Core1=INVALID
Core0 读，内存把这一行送进来，只有它持有干净副本
  Core0=EXCLUSIVE  Core1=INVALID
Core1 也读，两个核都是共享的干净副本
  Core0=SHARED  Core1=SHARED
Core0 写，Core1 的副本作废，Core0 成为唯一的脏副本
  Core0=MODIFIED  Core1=INVALID
Core1 再读，Core0 先把脏数据写回，两边重新共享
  Core0=SHARED  Core1=SHARED
```

第 4 步就是缓存行演示里“写 b 作废 a”的协议动作。锁和 `volatile` 最终都要落到这类作废和内存屏障上，否则另一核可以一直用自己的旧副本。

## 设备和中断

设备寄存器映射在一段地址上。CPU 可以反复读状态位，也可以等设备拉中断。中断打断当前指令流，进内核处理，再返回。中断里只做很短的登记，耗时工作交给后面的线程。

大批量数据走 DMA：设备直接把字节写入内存环，CPU 只在开始和结束时介入。网卡收 1500 字节的帧就是这样，见 [一次请求](../demos/src/RequestPath.java) 的第 1 步。
